## Core Model

The four stages of competence describe how any entity progresses from novice to master in a skill:

| Stage | Name | Characteristic |
|-------|------|----------------|
| 1 | Unconscious Incompetence | Doesn't know what they don't know |
| 2 | Conscious Incompetence | Aware of gaps, feels awkward |
| 3 | Conscious Competence | Can do it with focused effort |
| 4 | Unconscious Competence | Fluid execution without conscious attention |

## What Is Worth Stealing For Soul Code

### 1. GSK Progresses Through These Stages For Each Skill

Every skill GSK acquires should be stage-tracked:
- **Stage 1**: skill registered but not yet practiced
- **Stage 2**: skill used with errors, conscious awareness of gaps
- **Stage 3**: skill works reliably with focused attention
- **Stage 4**: skill is procedural — available without consuming working memory

This should live in the Lesson/Policy memory class.

### 2. The Memory Compiler Is Currently At Stage 2

The compiler exists but requires focused debugging and tuning to produce reliable fact/lesson extraction. Stage 3 is reached when it runs unattended with quality output. Stage 4 is reached when compiler consolidation becomes background noise that never needs attention.

This gives us a concrete maturity model.

### 3. Deliberate Practice = Background Compiler Cycle

The article identifies deliberate practice as the main accelerator. For Soul Code, the background compiler cycle IS deliberate practice for memory — focused, goal-oriented, feedback-driven.

### 4. Conscious Competence Maps To The Lesson Layer

When GSK is consciously aware of a lesson ("I must not launch body actions before hands are wired"), that lesson lives in conscious competence. When the lesson becomes automatic (the system never makes that mistake), it graduates to unconscious competence / procedural memory.

### 5. Unconscious Competence Maps To Procedural Memory

The final stage is when a skill no longer needs conscious attention. This is procedural memory. It's stored differently than facts — it's encoded in behavior, not in retrievable propositions.

## Design Implications

1. **Lesson status should include competence stage**
2. **Compiler cycles are deliberate practice, not passive maintenance**
3. **Procedural memory (stage 4) should be structured differently from declarative lessons**
4. **Feedback loops are not optional — stage 2 cannot become stage 4 without feedback**
5. **Mastery is not a destination but ongoing practice** — even at stage 4, continued use is required

## REDBUTTON Impact

Strengthens the case for:
- procedural memory as a distinct class
- lesson extraction pipeline with stage tracking
- background compiler as deliberate practice
- feedback and reflection as first-class governance functions

## One-Sentence Takeaway

The four stages of competence provide a maturity model for every skill and lesson in Soul Code, from clumsy first attempts to fluid procedural mastery.
