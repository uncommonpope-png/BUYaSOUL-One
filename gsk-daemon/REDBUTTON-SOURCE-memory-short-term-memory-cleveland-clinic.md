## Core Human Short-Term Memory Model

The source defines short-term memory as:
- temporary storage of recently learned information
- easily accessible
- limited in capacity and duration

Main functions:
- attention
- recognition

Core quantitative lesson:
- about five to seven items
- about 15 to 30 seconds

The source also distinguishes short-term memory from working memory:

- short-term memory = temporary storage
- working memory = temporary storage plus manipulation for reasoning, learning, and understanding

It notes that the prefrontal cortex temporarily stores short-term memories, while the hippocampus helps convert short-term memories into long-term memory.

## What Is Worth Stealing

### 1. Working Memory Must Be Strictly Bounded

This source strongly supports building Soul Code's working context as a bounded, curated layer.

Architectural lesson:
- do not confuse available tokens with genuine working memory
- the being should not try to keep everything active at once

Practical implications:
- limit active mission context
- limit concurrent priorities
- actively evict stale working-set items
- promote only selected items into durable memory

### 2. Attention And Recognition Are First-Class Functions

The source identifies two primary functions of short-term memory:
- attention
- recognition

That is important.

Soul Code should treat working memory not only as storage, but as the layer that:
- focuses attention
- matches new input against known patterns

This means working memory must hold:
- current task focus
- current salient entities
- current unresolved questions
- recognized matches from identity, relationship, and mission memory

### 3. Short-Term Memory And Working Memory Are Related But Not Identical

This distinction is very valuable.

Architectural translation:

- short-term memory = active accessible state
- working memory = active accessible state plus manipulation engine

So Soul Code should distinguish:

1. `Active Buffer`
- what is currently in awareness

2. `Working Manipulation Layer`
- what is currently being transformed, reasoned over, compared, or planned with

This prevents a major design mistake where context packing is treated as cognition.

### 4. Conversion To Long-Term Memory Needs Mechanism

The source explicitly says short-term material can move into long-term memory.

The key lesson is that this is not automatic or equal for everything.

The source names two mechanisms:
- chunking
- rehearsing

Soul Code equivalents:

#### Chunking
- package observations into structured episodes
- compress many local details into coherent units
- group related facts, relationships, and tasks

#### Rehearsal
- repeated retrieval
- repeated use in reasoning
- repeated invocation in behavior
- repeated emotional or mission relevance

This supports a memory compiler that uses:
- repeated access
- repeated mission significance
- repeated emotional relevance
as signals for promotion.

### 5. The Prefrontal Layer Matters

The source ties short-term memory to the prefrontal cortex.

Architectural analogue:
- the executive layer of Soul Code should own working memory management
- not the ledger
- not long-term semantic memory directly

This suggests a clean separation:
- executive working layer
- long-term autobiographical layer
- factual and procedural long-term layers

### 6. Working Memory Failure Is Not Just Forgetting

The source notes short-term memory supports:
- attention
- recognition
- later transfer to long-term memory

So short-term working failure in Soul Code could look like:
- losing task focus
- failing to match current input against known patterns
- failing to promote important material into durable memory
- overloading active context with too many items

This is important because many agent failures that look like reasoning failures may actually be working-memory failures.

### 7. Human Working Memory Is Vulnerable To Health And State

The article lists many causes of short-term memory impairment, including:
- injury
- medication
- depression
- PTSD
- neurodegeneration
- substance use

Soul Code analogue:
- body/tool instability
- context overload
- interruption storms
- stress-like error conditions
- corrupted retrieval state
- repeated failed loops

This supports the idea that working memory reliability should depend on system state, not be assumed constant.

## What Should Not Be Copied Naively

Do not copy these simplifications:

1. short-term memory is just a buffer
- in humans it also supports attention and recognition

2. working memory equals token window
- wrong; token availability is not the same as active manipulable cognition

3. transfer to long-term memory is automatic
- it must be selective and structured

4. bigger active memory is always better
- no; bounded active sets increase coherence
